# Safecast — 건설현장 폭염 관제 대시보드

기상청 예보를 **법정 판정 단위로 변환**해, 폭염 조치를 시각 단위로 산출하는 시스템입니다.

> 대한토목학회 캡스톤 디자인 경진대회 출품작

---

## 문제

고용노동부 「폭염 대비 사업장 대응지침」(2026.5)에 따르면, 온열질환 산재 사망자 31명 중 **25명(80.6%)이 폭염작업 투입 7일 이내**에, **13명(41.9%)이 첫날**에 발생했습니다.

법령은 체감온도 33℃ 이상에서 매 2시간 이내 20분 휴식을 의무화하고 있으나, 현장에는 세 가지 간극이 있습니다.

| 간극 | 내용 |
|---|---|
| **판정 단위** | 예보는 1시간 단위, 조치는 공정 단위로 이뤄진다 |
| **대상 선별** | 민감군을 누가 어떻게 가려내는가가 정해져 있지 않다 |
| **기록** | 체감온도·조치사항 기록이 의무이나 수기로는 지켜지지 않는다 |

---

## 해결 — 알고리즘 3

### 1. 공정 블록화 + 보수적 MAX

1시간 예보를 공정 블록으로 묶고, 블록 내 최고 위험온도를 블록 전체에 적용합니다.

```
오전 1부  08–10    오전 2부  10–12    점심  12–14
피크      14–17    마무리    17–18
```

**근거** — 안전보건규칙 별표13의2는 "측정값이 가장 높은 장소"를 기준으로 하도록 정합니다(공간축 MAX). 본 시스템은 인체 열 축적을 근거로 이를 시간축으로 확장했습니다. 두 축의 일관성이 방어 논리입니다.

**오전을 2시간으로 나눈 이유** — 블록이 길수록 1시간 스파이크의 오염 범위가 넓어집니다. 4시간 블록에서는 11시 하나가 34.9℃면 08시(32.9℃)까지 상향됩니다. 2시간은 법정 휴식 주기(제560조제3항)와도 일치합니다.

피크 14–17시는 지침이 정한 무더위 시간대이므로 쪼개지 않습니다.

### 2. 열순응 시각 환산

지침 19쪽의 열순응 프로그램을 **작업 종료 시각**으로 변환합니다.

```
신규 투입  1일 20% → 2일 40% → 3일 60% → 4일 80% → 5일 100%
복귀(7일↑) 1일 50% → 2일 60% → 3일 70% → 4일 80% → 5일 100%

8시간 × 20% = 1시간 36분 → 08:00 시작이면 09:36 종료
```

비율만 표시하면 관리자가 매번 환산해야 하고, 환산하지 않으면 지켜지지 않습니다.

### 3. 민감군 자동 선별

출역 데이터에서 민감군 8유형을 자동 분류하고, 체감온도 38℃ 이상에서 옥외작업 제한 대상을 산출합니다.

```
① 만성질환  ② 온열질환 기왕력  ③ 고령(65세↑)  ④ 약물복용
⑤ 알코올의존  ⑥ 고강도 작업  ⑦ 신규배치  ⑧ 일시적 건강저하
```

**시스템은 판정하지 않고 선별·기록합니다.** 근로 제한의 최종 판단은 관리자와 의사의 몫입니다.

## 정확도 — 지점 상세화 보정

### 왜 예보를 대체하지 않는가

조창제(2020)는 지상관측 604지점을 공간보간해 LSTM·공간랜덤포레스트로 기온 예측모형을 만들고 동네예보와 비교했습니다.

| 모형 | 시간단위 RMSE |
|---|---|
| 기상청 동네예보 | 3.2 ~ 7.6℃ |
| PCA 공간랜덤포레스트 | 7.0 ~ 8.6℃ |
| LSTM | 11 ~ 25℃ |

슈퍼컴퓨터 수치예보를 관측자료 기반 모형으로 대체하는 것은 실효성이 없습니다. 본 시스템은 **동네예보를 출발점으로 삼아 보정**하며, 보정량이 0이면 원본과 동일하므로 성능 하한이 보장됩니다.

### 고도 기온감률 보정

관측소는 노장해발고도(HT)와 온도계 지상높이(HT_TA)를 공개하므로 **기준 고도가 확정**됩니다. 격자 대표고도는 공개되지 않아 보정식이 성립하지 않습니다.

```
현장값 = 관측값 + (현장고도 − 기준고도) × 월별 기온감률
```

김용석 외(2014)에서 기온감률 적용 시 공간내삽 RMSE가 26~37% 개선되었고, 산지가 많은 강원도에서 감소폭이 가장 컸습니다.

**기준 지점은 거리와 고도차를 함께 고려**해 선정합니다. 보정량이 클수록 감률의 불확실성이 증폭되므로, 가깝기만 한 지점보다 고도가 비슷한 지점이 유리할 수 있습니다.

### 습도 재계산

선행연구 3편 모두 기온만 다룹니다. 그러나 법정 판정 기준은 체감온도이며, 기온을 보정하면 이슬점이 보존된 채 **상대습도가 변합니다**.

```
격자 30℃ / 60%  →  고도 보정 −3.4℃  →  26.6℃
  습도 60% 유지     → 체감 27.1℃   ← 오차
  습도 73% 재계산    → 체감 28.1℃   ← 정확
```

생략하면 체감온도를 약 1℃ 과소평가하며, 그 방향이 항상 '실제보다 시원함'이라 안전 관점에서 위험합니다.

### 격자별 예보 편의 — 실측 검증

수집한 예보·실황 쌍으로 여러 보정 방법을 롤링 검증했습니다.

| 방법 | RMSE | 등급정확도 | 과소판정 |
|---|---|---|---|
| 보정 없음 | 1.074 | 82.1% | 7.7% |
| 전국 시간대별 | 1.055 | 83.8% | 9.7% |
| **격자별 상수** | **0.947** | **85.0%** | **6.6%** |
| 격자별 시간대 | 0.908 | 85.4% | 10.2% |

**격자별 상수를 채택했습니다.** RMSE가 가장 낮은 것은 격자별 시간대였으나 **과소판정이 7.7%→10.2%로 증가**해 부적합합니다. 과소판정은 휴식 미부여로 이어지므로 과대판정보다 위험합니다.

시간대별 편의를 배제한 이유는 안정성입니다. 2주 내에 평균 0.39℃ 변동했고 부호가 바뀌는 시각도 있어, 예보 모델의 구조적 편의가 아니라 해당 기간의 기상 패턴으로 판단했습니다.

## 법적 근거

### 의무와 권고

| | 성격 | 위반 시 |
|---|---|---|
| 산업안전보건기준에 관한 규칙 | **의무** | 산안법 제168조 — 5년 이하 징역 또는 5천만원 이하 벌금 |
| 폭염 대비 사업장 대응지침 | 권고 | 직접 처벌 없음 |

앱은 조치사항마다 이 구분을 표시하며, **「법적 의무만 보기」** 토글로 법정 최소 기준만 볼 수 있습니다.

> 예: 체감온도 35℃에서 지침은 매시간 15분 휴식을 권고하나, **법적 최소는 여전히 2시간마다 20분**(제560조제3항)입니다.

### 주요 조문

| 조문 | 내용 |
|---|---|
| 제558조제4호 | 폭염 정의 |
| 제559조제4항 | 측정 곤란 시 기상청 체감온도 활용 가능 |
| 제560조제2항 | 31℃ — 냉방·시간조정·휴식 중 1개 이상 |
| 제560조제3항 | 33℃ — 매 2시간 이내 20분 이상 휴식 |
| 제562조제2항 | 온·습도계 비치 / 사전 주지 / **일자별 기록·연말까지 보관** |
| 제567조제2항 | 옥외 그늘진 장소 제공 |
| 제571조 | 소금과 음료수 비치 |

권고 사항이라도 미이행 시 방어가 어렵습니다. 고용노동부가 "사망자의 41.9%가 투입 첫날"을 공개 문서로 공표한 이상, **예견가능성** 측면에서 "몰랐다"가 성립하지 않기 때문입니다.

## 한계

**현장 미기후는 보정할 수 없습니다.** 관측소는 잔디 위 백엽상, 건설현장은 콘크리트·철골입니다. 그 격차는 관측 데이터에 정보가 존재하지 않으므로 어떤 통계적 보정으로도 제거되지 않습니다.

→ 실측 센서 연동이 필요하며, 센서값이 있으면 항상 그쪽을 우선하도록 설계했습니다.

**조치 완료 확인은 의도적으로 수동입니다.** 시스템이 스스로 "이행함"이라 기록하면 허위 기록이며, 근로 관련 판단은 법령상 사람의 영역입니다.

## 구조

```
app.py           기상 데이터 · 블록화 · 알람 · 화면
tbm.py           민감군 · 열순응 · TBM 명단 · 자각증상
records.py       조치 기록 (제562조제2항제3호)
correction.py    고도 기온감률 · 습도 재계산 · 격자 편의
stations.py      ASOS/AWS 지점 연동
snapshot.py      수집 데이터 fallback

scripts/
  collect.py            예보·실황 수집 (Actions가 30분마다)
  analyze_bias.py       편의 분석·학습
  compare_corrections.py 보정 방법 롤링 검증
  check_data.py         수집 데이터 진단
  fetch_stations.py     지점목록 내장

data/
  forecast_log.csv      수집 예보
  obs_log.csv           수집 실황
  site_bias.csv         격자별 편의
  stations_*.csv        지점목록 (위경도·고도)
```

### 데이터 공급 경로

API 상태와 무관하게 동작하도록 4단계로 구성했습니다.

```
① 라이브   공공데이터포털 → 기상청 API허브
② 스냅샷   GitHub Actions가 수집한 실제 예보 (최대 30분 지연)
③ 데모     API·스냅샷 모두 불가 시 (판정 사용 금지 배너 표시)
```

지점목록은 레포에 내장되어 있어, API가 막혀도 **관측소 고도 기준 보정은 유지**됩니다.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

`.streamlit/secrets.toml`

```toml
KAKAO_KEY   = "카카오 REST API 키"          # 주소 → 좌표
KMA_KEY     = "공공데이터포털 일반인증키(Decoding)"
KMA_HUB_KEY = "기상청 API허브 authKey"       # 선택 — 이중화용
ADMIN_PW    = "관리자 비밀번호"
```

수집 자동화는 GitHub Actions Secrets에 `KMA_KEY`를 등록하면 동작합니다.
